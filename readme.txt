========================================================================
企业知识库 RAG 问答系统 - 使用说明
========================================================================

一、项目简介
------------------------------------------------------------------------
基于 FastAPI + LanceDB 的企业项目文档知识库问答系统。
核心能力：
  - 三路召回检索：向量(cosine) + BM25 全文 + 图谱(实体双链倒排)，RRF 融合排序
  - 智能路由：按问题难易自动分档（简单/复杂/实体），也可手动选模式
  - SSE 流式问答：答案逐字输出，前端实时渲染
  - 检索过程全透明：切片卡片、命中通道、相似度、路由原因、提示词均可查看
  - 实体检索可视化：实体核心 -> 关联文档的知识图谱

二、目录结构
------------------------------------------------------------------------
app.py                FastAPI 服务入口（/ 页面、/api/meta 库信息、/api/ask SSE 问答）
config.py             全局配置：从 .env 读取，路径基于本文件所在目录解析
chunking.py           文档解析与章节切片（按 H2/H3 边界打包，单块 <= 2000 字符）
embedder.py           Embedding 客户端（OpenAI 兼容接口 / 无 Key 时 mock）
ingest.py             全量入库：Raw 文档 -> 切片 -> 向量化 -> LanceDB（含 BM25 索引）
pipeline.py           Prompt 组装 + LLM 流式生成
retriever.py          检索模块：向量 + BM25 + 图谱多路召回，RRF 融合
router.py             查询路由器：判定简单/复杂/实体三档，抽取实体与元数据过滤
wiki_graph.py         Wiki 实体词典构建与实体抽取（词典匹配）
migrate_entities.py   一次性迁移脚本：为旧 LanceDB 表补 entities 列
start.bat             Windows 一键启动脚本
requirements.txt      Python 依赖清单
.env                  实际配置（含 API Key，不要外传/提交 git）
.env.example          配置模板
data/lancedb/         LanceDB 向量库（由 ingest.py 生成）
static/               前端页面（index.html）
Raw/                  原始文档库（.md 文件，104 篇）
Wiki/                 实体词典库（index.md 实体索引 + entity/concept 目录）

三、运行步骤
------------------------------------------------------------------------
1. 环境：Windows + Python 3.10 及以上（代码使用 int | None 等新语法）

2. 安装依赖：
   pip install -r requirements.txt

3. 配置 .env（参考 .env.example，当前已配好 DashScope Embedding + DeepSeek LLM）：
   EMBEDDING_*   Embedding 接口（任意 OpenAI 兼容端点）
   LLM_*         LLM 接口（任意 OpenAI 兼容端点）
   RAW_DIR       原始文档目录，默认 ./Raw
   LANCEDB_DIR   向量库目录，默认 ./data/lancedb
   TOP_K         默认检索条数，默认 8

4. 文档入库（首次使用、或 Raw/Wiki 有更新时执行）：
   python ingest.py            全量入库（覆盖旧表）
   python ingest.py --limit 3  只处理前 3 篇（冒烟测试，省 API 调用）
   python ingest.py --stats    只看切片统计，不调用 API

5. 启动服务：
   双击 start.bat
   （或命令行: python -m uvicorn app:app --host 127.0.0.1 --port 8000）

6. 浏览器访问 http://127.0.0.1:8000

四、检索逻辑
------------------------------------------------------------------------
1) 路由分档（router.py，auto 模式下执行）
   - 简单：单一事实查询，答案通常在一个文档内（预算/日期/负责人等）
           -> 向量 + BM25 双路召回；唯一客户/项目类型时加元数据预过滤
   - 复杂：跨文档聚合/对比/列表/多跳（如"哪些客户做过XX项目"）
           -> 再叠加图谱召回，三路融合
   - 实体：LLM 抽出的关键词命中 Wiki 词典的实体/概念
           -> 跳过向量与 BM25，按实体名扫描 Raw 全部文件的 [[双链]] 命中段落
   判定优先级：聚合/对比类模式词（哪些/列出/汇总/对比等）直接判复杂；
   否则调 LLM 判定并抽关键词；LLM 失败退回简单。
   关键词全是泛概念时不触发实体扫描，退回简单模式。

2) 三路召回（retriever.py）
   - 向量：查询与切片 embedding 的 cosine 相似度（相似度 = 1 - 距离）
   - BM25：jieba 分词后对 text_tokens 列做全文检索
   - 图谱：Wiki 实体 -> Raw [[双链]] 倒排（entities 列 contains 查询），
           按命中实体数排序，属文档级召回

3) 融合与排序
   - RRF 融合：各通道按排名贡献 1/(60+排名)，累加成融合分，按融合分降序
   - 复杂模式：同一文档的多个切片只保留融合分最高的（防止单文档霸屏）；
     具体实体链接到的文档全部补全进结果（允许超过 top_k，让答案更全）
   - 元数据预过滤：过滤后为空则自动回退全库检索

4) 实体扫描的分层召回（防止高频概念把几十篇文档灌满提示词）
   - 具体实体（客户/项目类型/人名/部门/技术组件）作硬约束，多词取交集
   - 概念、以及命中文档占比超 40% 的泛概念，只参与排序加分
   - 交集为空时逐级回退并集，绝不归零
   - 同类多实体（如 中国移动 + 中国联通）视为对比场景，不取交集、各取一批
   - 每篇只注入 [[实体]] 命中段落及邻近小节（<= 800 字符）；
     命中文档不足 5 篇时改为整篇原文注入（材料少则给全）

5) 生成（pipeline.py）
   - 检索切片拼成【参考资料】，系统提示词要求 LLM 仅依据资料作答，
     数字/日期/金额/人名必须与原文一致，引用处标 [文档N]
   - SSE 流式输出，前端逐字渲染；LLM 未配置时跳过生成，仅展示检索结果

五、前端页面说明
------------------------------------------------------------------------
- 检索模式可选：auto（智能路由）/ hybrid（向量+BM25）/ vector / fts / entity（实体扫描）
- 切片卡片的通道标签只显示一个，优先级：实体命中 > 图谱 > 双侧 > 向量 > 关键词
  （例：显示"图谱"且带相似度百分比的切片，实际是图谱+向量双侧命中）
- 卡片上的相似度百分比 = 向量通道的 cosine 相似度；列表排序依据是 RRF 融合分
- 实体检索模式下右侧展示知识图谱（实体核心 -> 关联文档，最多画 24 个文档节点）

六、注意事项
------------------------------------------------------------------------
1. .env 含 API Key，不要提交到 git 或发给他人
2. Raw 文档更新后必须重新运行 python ingest.py（全量覆盖式重建，会重新调
   Embedding API）；只改 Wiki 词典则无需重新入库
3. Raw 文件名必须符合"客户_项目类型_文档类型_YYYYMMDD.md"格式，
   否则元信息（客户/项目类型等）解析为空
4. Raw 正文中用 [[实体名]] 双链标记实体，图谱召回与实体扫描都依赖它；
   Wiki 词典来自 Wiki/index.md 的实体索引 + entity/concept 目录的文件名，
   新增实体后重启服务生效（词典在内存中有缓存）
5. EMBEDDING_DIM 必须与所用 Embedding 模型一致（当前 text-embedding-v4 = 1024）；
   更换模型或维度后需重新入库，否则向量检索会报维度不匹配错误
6. 服务默认占用 8000 端口，start.bat 启动时会检测占用并提示
7. 无 API Key 想先跑通流程时，.env 中设 EMBEDDING_PROVIDER=mock
   （哈希向量无语义能力，仅用于验证链路）
8. migrate_entities.py 是一次性迁移脚本，仅在旧向量表缺 entities 列时使用，
   正常流程不需要运行
