## 1. 架构概述
本架构为[[国家电网]][[ERP系统]]财务模块专属设计，覆盖全国27个省级电力公司、168家地市分公司、12.6万财务及业务相关用户，替代2018版老旧[[ERP]]财务模块，实现财务核算、[[预算管理]]、资金管控、税务管理、[[报表]]分析全流程线上化、智能化，预期财务处理效率提升32%，审计[[合规]]率达100%。
架构整体采用[[云原生]][[微服务]]设计，符合[[国家电网]]《信息系统技术规范V5.0》、[[等保2.0]]三级要求，所有操作日志留存期满足财务审计7年追溯要求。

## 2. 架构设计原则
| 原则 | 具体要求 |
| --- | --- |
| [[合规]]优先 | 所有功能、数据流程符合《电力行业财务信息管理规范》《[[国家电网]][[数据安全]]管理办法》，敏感数据全链路加密 |
| [[云原生]]可扩展 | 所有服务支持弹性扩缩容，可支撑未来5年用户规模增长30%的业务需求 |
| 低耦合高内聚 | [[微服务]]边界清晰，单一服务故障不影响全局业务，服务[[迭代]]周期不超过2周 |
| 可观测可追溯 | 全链路请求可追踪，所有数据变更留痕，故障定位时间不超过10分钟 |
| 利旧降本 | 复用[[国家电网]]现有私有云基础设施、[[SSO]]身份体系、密钥管理系统，降低硬件投入成本180万元 |

## 3. 系统架构图描述
系统采用分层[[分布式]]架构，从下到上分为5层，配套3个横切支撑体系：
1. **基础设施层**：部署于[[国家电网]]私有云华北、华东双可用区，共配置128台计算节点（单节点Intel Xeon 8375C 32核/128G）、2.4PB[[分布式]]存储，跨可用区网络带宽峰值10Gbps
2. **[[PaaS]]支撑层**：包含[[Kubernetes]]容器编排集群、[[微服务]]治理组件、[[中间件]]集群、数据库集群，提供通用技术能力支撑
3. **业务服务层**：所有业务能力以[[微服务]]形式部署，对外提供标准化[[gRPC]]/HTTP接口
4. **接入层**：包含[[API网关]]、SLB[[负载均衡]]、统一[[身份认证]]组件，负责流量接入、权限校验、流量管控
5. **展示层**：覆盖PC管理端、国网移动端APP插件、财务决策大屏三类终端
6. **横切支撑体系**：安全管控体系、[[监控运维]]体系、[[数据治理]]体系，覆盖所有层级的安全、运维、数据管理需求

## 6. 数据架构
数据按冷热分层存储，所有数据符合《[[国家电网]]财务数据元标准V3.0》：
1. **数据分层策略**
   - 热数据（近12个月业务数据）：存储于[[MySQL]]集群，总容量48TB，3副本，[[分库分表]]规则：按省级单位编码分27个库，按会计年月分120张表
   - 温数据（1-5年历史数据）：存储于[[ClickHouse]]集群，总容量192TB，2副本，采用[[Canal]] v1.1.6实现[[MySQL]]增量数据同步，同步延迟≤5秒
   - 冷数据（5年以上归档数据）：存储于国网对象存储，总容量1.2PB，3副本，压缩比≥5:1
2. **数据备份策略**
   - 每日凌晨2点执行全量备份，每15分钟执行增量备份，备份数据跨可用区存放
   - 数据恢复指标：RPO≤15分钟，RTO≤30分钟，满足财务[[业务连续性]]要求

## 7. 安全架构
符合[[等保2.0]]三级要求，安全测评预算85万元，计划2024年12月完成测评：
1. **[[身份认证]]**：统一接入国网[[SSO]]体系，支持UKey、人脸、短信多因素认证，密码有效期90天，连续5次登录失败锁定账户30分钟
2. **传输安全**：所有请求采用HTTPS TLS1.3协议加密，敏感字段（银行账号、纳税人识别号）采用SM4国密算法单独加密
3. **存储安全**：敏感数据落盘采用AES-256加密，密钥存储于国网KMS密钥管理系统，每月自动轮换密钥
4. **[[数据脱敏]]**：[[前端]]展示敏感字段自动脱敏，银行账号仅显示后4位，身份证号中间10位打码
5. **操作审计**：所有用户操作、接口调用日志全量采集存储于[[Elasticsearch]]集群，留存期7年，满足审计追溯要求
6. **边界防护**：集成国网WAF/IPS系统，每周更新攻击规则，SQL注入、XSS攻击拦截率≥99.99%，[[告警]]响应时间≤5分钟

## 8. [[高可用]]设计
系统年可用率目标≥99.95%，年 downtime ≤4.38小时：
1. **多可用区[[容灾]]**：双可用区对等部署，流量采用DNS[[负载均衡]]，单可用区故障自动切流，切换时间≤10秒，每年开展2次[[容灾]]演练
2. **组件无单点**：所有[[中间件]]、数据库均为集群部署，[[MySQL]]一主两从自动切换，[[Redis]]集群自动故障转移，无单点故障风险
3. **[[限流]]降级**：采用[[Sentinel]] v1.8.6实现[[限流]]降级，核心接口（资金支付、总账记账）优先级最高，非核心接口（[[报表]]导出、日志查询）流量过高时自动降级
4. **故障自愈**：[[Kubernetes]]配置存活探针、就绪探针，故障实例自动重启、漂移，平均故障恢复时间≤2分钟

## 9. 性能设计
性能指标满足业务峰值2.5倍冗余要求，全链路压测计划2024年11月执行，压测投入成本22万元：
| 指标项 | 性能要求 |
| --- | --- |
| 核心接口响应 | 总账记账、资金支付、预算申报等核心接口平均响应时间≤200ms，99分位响应时间≤500ms |
| 并发能力 | 支持最高1.2万并发用户访问，峰值QPS≥8000 |

| 静态资源加载 | 接入国网[[CDN]]，静态资源加载时间≤1.5秒 |
| [[缓存]]命中率 | 核心热数据[[缓存]]命中率≥95% |

## 10. [[监控运维]]方案
运维团队7*24小时值守，负责人：周凯（运维组主管）：
1. **监控体系**：采用[[Prometheus]] v2.47.2 + [[Grafana]] v10.1.2实现[[全链路监控]]，覆盖基础设施、[[中间件]]、业务服务三个层面，共配置1286项监控指标
2. **日志体系**：采用ELK Stack v8.9.0实现[[日志采集]]、分析，[[日志采集]]延迟≤10秒，支持按请求ID全[[链路追踪]]
3. **[[告警]]体系**：采用Alertmanager实现多渠道[[告警]]，[[告警]]分为三级：P1级（核心业务故障）电话+短信[[告警]]，响应时间≤5分钟；P2级（非核心故障）[[企业微信]]+短信[[告警]]，响应时间≤30分钟；P3级（预警类[[告警]]）[[企业微信]][[告警]]，响应时间≤2小时
4. **发布体系**：采用[[GitLab]] [[CI/CD]]实现自动化部署，支持[[灰度发布]]，发布流量从10%逐步放量至100%，平均发布时间≤15分钟，版本回滚时间≤2分钟
